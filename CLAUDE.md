# Скрипты Umbrella (Dota 2)

Это папка `scripts` чита Umbrella. Каждый `.lua` в корне — отдельный скрипт, который чит грузит в игру.
Подпапки (`self_play/`, `mock/`) — модули, их грузят через `require`.

## Перед тем как писать код

1. **API — только из `UMBRELLA_API.md`.** Это полный справочник v2.0, сгенерированный из официальной
   документации (https://uczone.gitbook.io/api-v2.0), по строке на функцию. Перед вызовом любой функции
   чита найди её там грепом. Нет в файле — значит нет в игре. Не придумывай «логичные» имена:
   `NPC.GetPosition` не существует, существует `Entity.GetAbsOrigin`.
2. **Проверяй в моке, а не в игре.** После любой правки:

   ```bash
   lua mock/run.lua имя_скрипта.lua --brief --keep-going
   ```

   Код выхода 0 — чисто. 1 — в отчёте есть ошибки, несуществующие функции или неверное число аргументов.
   Чини, пока не будет 0, и только потом говори, что готово. `--keep-going` нужен, чтобы за один прогон
   увидеть все ошибки, а не первую в каждом колбэке; финальную проверку делай без него — так ведёт себя игра.
   Бинды нажимаются по имени или номеру: `--press 30:"За мной"` или `--press 30:#1` (тик 30),
   настройки ставятся через `--set "Включить=true"`. Подробно — `MOCK.md`.
3. **Не дублируй встроенное.** Что чит умеет сам (мапхак, ластхит, комбо, доджер, killsteal...) —
   в `UMBRELLA_FEATURES.md`. Предлагая идею скрипта, сначала сверься с ним.
4. Мок — не игра. Функции, которые он не симулирует, он перечисляет в отчёте («не симулируется»).
   Логику, завязанную на них, в прогоне ты по-настоящему не проверил — так и скажи пользователю.

## Как устроен скрипт

```lua
---@diagnostic disable: undefined-global

local script = {}

function script.OnScriptsLoaded() end   -- один раз, здесь строится меню
function script.OnUpdate() end          -- каждый тик игры: логика
function script.OnDraw() end            -- каждый кадр: только рисование

return script                           -- обязательно вернуть таблицу
```

- Имена колбэков чит сверяет **точно**. Опечатка — не ошибка, функция просто никогда не вызовется.
  Полный список — раздел `## Callbacks` в `UMBRELLA_API.md`.
- `print(...)` и `log(...)` пишут в `../debug.log` (папка чита, на уровень выше `scripts`).
  Там же видны ошибки Lua из игры.
- Всё держи в `local`. Глобальные переменные не заводи.
- `require` ищет модули в двух местах: в `scripts/` (`require("self_play.awareness")`) и в папке
  самого чита (`require("assets.JSON")` → `../assets/JSON.lua`). Библиотеки чита `protobuf` и `chronos`
  подключаются только через `require("protobuf")`, глобалами они не являются.
- У чита есть глобалы, которых нет в документации: `XHelpers` (парсер KV-файлов доты, на нём сидит
  `self_play`) и `db` (встроенное хранилище). Их сигнатуры никто не описал — используй только так,
  как они уже используются в существующих скриптах, и скажи пользователю, что это не по доке.

## Язык

Lua **5.4**, не LuaJIT (в скриптах работают `"\u{f0e7}"` и `goto`). Отсюда:

- `math.atan2` в 5.4 нет — пиши `math.atan(y, x)`.
- Битовые операции встроены: `Ability.GetBehavior(ab) & Enum.AbilityBehavior.DOTA_ABILITY_BEHAVIOR_NO_TARGET ~= 0`.
- Доступ к файлам режется песочницей чита (в `debug.log`: `[Lua security] file access denied`).
  Для сохранения настроек — `Config.*`, не `io.open`.

## Грабли, на которые уже наступали

- **Entity и NPC.** `CNPC` расширяет `CEntity`. Позиция, здоровье, команда, жив/нет, индекс — это
  `Entity.*` (`Entity.GetAbsOrigin`, `Entity.GetHealth`, `Entity.GetTeamNum`, `Entity.IsAlive`).
  Всё про юнита как юнита — `NPC.*` (`NPC.GetUnitName`, `NPC.GetAttackRange`, `NPC.HasModifier`).
- **`World.GetGroundZ(x, y)`** — два числа, не вектор. С вектором молча вернёт мусор/nil.
- **nil — нормальный ответ.** `NPC.GetAbility`, `NPC.GetItem`, `NPC.GetModifier`, `Heroes.GetLocal`
  (в меню) законно возвращают nil. Проверяй результат, прежде чем передать его дальше.
- **`OnUpdate` — это каждый тик.** Приказ, отданный оттуда без ограничения, уходит десятки раз в секунду:
  юнит дёргается на месте, чит начинает глотать приказы. Держи интервал на юнита и не повторяй
  одинаковый приказ. Бюджет чита можно спросить: `Humanizer.IsSafeToCastOrder()`.
- **`OnDraw` и `OnUpdate` идут только в матче, а `OnKeyEvent` — везде, включая главное меню.**
  Если блокируешь ввод (`return false`), делай это только пока твой `OnDraw` реально рисует
  (проверяй время последнего кадра) и только при `Engine.IsInGame()`. Иначе вне матча скрипт
  молча съест все клавиши и клики, а выйти будет нечем. Всегда оставляй аварийную клавишу.
- **В песочнице чита нет `coroutine`** (проверено: `attempt to index a nil value (global 'coroutine')`).
  Мок тоже обнуляет `coroutine`. Длинные сценарии пиши списком шагов или таймерами в `OnUpdate`.
  `utf8` не проверен, на него лучше не опираться: символы UTF-8 перебирает шаблон
  `"[%z\1-\127\194-\244][\128-\191]*"`. `debug`, `os.clock`, `os.time`, `pcall`, `xpcall` работают.
- **PNG из файлов `Render.LoadImage` не грузит** ни из `scripts`, ни из `images` (`"~/..."`).
  Работает PNG, вшитый base64 в SVG, через `Render.LoadSvgString(svg, Vec2(w, h), id)`.
- **`Engine.PlayVol(путь, громкость)` играет файл звука доты по пути**, например
  `"sounds/ui/ping_warning.vsnd_c"`, а не имя события. Список путей и длины - через
  `python engine3d/tools/find_sounds.py слово`. Остановить звук нельзя.
- **UV больше 1 не повторяют текстуру**, край растягивается полосами. Нужен повтор - режь сам.
- **Приказ посреди замаха отменяет удар.** Урона нет, а кулдаун атаки тикает. Двигать юнита можно
  только после момента схода удара (`OnUnitAnimation` → `data.castpoint`).
- **Меню строится по уровням.** Каждое имя в `Menu.Create(...)` — шаг на уровень глубже
  (`CFirstTab` → `CTabSection` → `CSecondTab` → `CThirdTab` → `CMenuGroup`). Виджеты (`Switch`,
  `Slider`, `Bind`...) есть **только** у `CMenuGroup`. Рабочий шаблон:

  ```lua
  local tab   = Menu.Create("Scripts", "Utility", "Имя скрипта", "Main")  -- CThirdTab
  local group = tab:Create("Основное", Enum.GroupSide.Left)             -- CMenuGroup
  local on    = group:Switch("Включить", true, "\u{f0e7}")
  on:ToolTip("Что делает эта галочка.")
  ```

  Если вызвать `Switch` у таба, меню молча не построится. Мок такое ловит.
- **Переменные цикла `for` в чите только для чтения** (как в Lua 5.5): `for part in s:gmatch(...) do part = ... end`
  роняет загрузку скрипта с `attempt to assign to const variable`, и скрипт не появляется в меню. Мок на обычном
  Lua 5.4 это пропускает. Нужна другая переменная: `local p = part:match(...)`.
- **engine3d/render.lua: не ограничивай число заходов в сектор при обходе порталов** - выброшенное окно
  оставляет незакрашенные столбцы (чёрные штрихи). Лишние заходы убираются владельцем столбца (`owner`)
  и слиянием ждущих записей очереди.
- **`Camp.GetCampBox` - это зона блока спавна, крипы стоят не в её центре**, а бывает в 700-1000 от него.
  Нейтралов к кемпу привязывай по ближайшему кемпу в радиусе ~1100, иначе кемп с крипами покажется пустым.
- **В моке `globals` сценария не подменяют неймспейсы API** (`Camps`, `Towers`...): мок ставит свои
  заглушки поверх. Подменяй их в обёртке, которая выставляет глобалы и потом делает `loadfile` скрипта.
- **`Vector:Rotated(число)`** — единицы (градусы или радианы) в доке не указаны. Мок считает градусами.
  Если от этого что-то зависит — проверь в игре и допиши сюда.

## Приказы юнитам

Сигнатура по доке:

```lua
Player.PrepareUnitOrders(player, type, target, pos, ability, issuer, issuer_npc,
    [queue], [show_effects], [callback], [execute_fast], [identifier], [force_minimap])
```

- `issuer = Enum.PlayerOrderIssuer.DOTA_ORDER_ISSUER_PASSED_UNIT_ONLY` и юнит в `issuer_npc` —
  приказ ровно этому юниту. `DOTA_ORDER_ISSUER_SELECTED_UNITS` — всем выделенным.
- `callback = false` — приказ не пройдёт через `OnPrepareUnitOrders` (ни свой, ни чужих скриптов).
- `identifier` — строка-метка твоего скрипта.

Для управления призванными юнитами (волки, крипы Чена, медведь, клоны) есть готовая библиотека
`micro.lua` — не пиши это заново. Документация — `MICRO.md`.

## Мозг: записи действий игрока и нейросеть

`brain.lua` (скрипт) + `brain/core.lua` (модуль). Скрипт пишет каждый приказ игрока и события
(киллы, смерти, ластхиты, денаи) отдельно по каждому герою и онлайн учит маленькую нейросеть
(12 признаков → 16 → 14 классов действий) угадывать следующее действие. Меню: Scripts → Utility → Мозг.

**Где лежат данные.** Только через `Config` (`io` в песочнице закрыт): конфиг `brain/<герой>`, например
`brain/lycan`, в папке конфигов чита. Если чит не даёт `/` в имени конфига (проверяется пробной
записью при первом обращении), имя будет `brain_<герой>`. Папки руками не создавай. Что чит
реально создаёт папку - **в игре не проверено**, как и лимит длины строки в конфиге (кусок 1500 символов).

**Формат.** Ключи конфига: `c1..c400` - кольцевой буфер кусков (старые затираются), `head`, `chunks`,
`columns`. В куске строки через `;`, поля через `,`:
- действие: `a,t,cls,order,ability,target,px,py,tx,ty,<12 признаков>` - `t` время доты, `cls` номер
  в `core.CLASSES`, `order` - `Enum.UnitOrder`, `target` - `h` герой / `c` крип линии / `n` нейтрал /
  `b` здание / `u` другое / `-` нет, `px,py` где стоял герой, `tx,ty` куда приказ;
- событие: `e,t,kind,name` - `kind`: `kill`, `death`, `lasthit`, `deny`, `deny_hero`, `destroy`.
- веса сети: `net_1..net_n`, `net_shape`, `seen`, `hit`, `acc`.

**Как читать из своего скрипта:**

```lua
local core = require("brain.core")
local recs = core.read("lycan")             -- все записи героя, от старых к новым
for _, r in ipairs(recs) do
    if r.kind == "a" then print(r.t, core.CLASSES[r.cls], r.ability, r.f[1]) end   -- r.f - признаки
    if r.kind == "e" then print(r.t, r.event, r.name) end
end

local net = core.loadNet(core.heroKey(Heroes.GetLocal()))   -- обученная сеть героя
local probs = net:forward(core.features(hero))              -- вероятности по core.CLASSES
local best, p = net:best(probs)
```

Признаки (`core.FEATURES`, все 0..1): hp, mana, уровень/30, время/3600, вражеские герои в 1200 / 5,
союзники / 4, вражеские крипы в 800 / 10, дистанция до ближайшего врага, hp самого слабого крипа,
готовые скиллы / 4, рядом вражеская вышка, получал урон за 2 с. Меняешь список - меняется `net_shape`,
старая сеть не загрузится и начнёт с нуля (данные остаются, но старые строки будут с другими колонками).

Проверка в моке: `lua mock/run.lua brain.lua --scenario mock/examples/brain_scenario.lua`.
Не проверено в игре: путь конфига, приходит ли у приказов игрока `identifier == nil`
(скрипт отбрасывает приказы с меткой, считая их чужими скриптами), нагрузка от отрисовки сети (~400 линий в кадр).

## 3D-игры поверх доты

`engine3d.lua` + папка `engine3d/` — движок в духе Doom (портальный рендер столбцами через
`Render.Image` с UV, свой ввод через `OnKeyEvent`). Документация — `ENGINE3D.md`. Своя игра —
`engine3d/games/<имя>/game.lua` и строка в `engine3d/games/list.lua`. Уровни рисуются в
`engine3d/tools/editor.html`. Мок проверяет API и логику, но картинку не рисует.
Игра без 3D (вид сверху, своя отрисовка) - это `game.draw(e)` без `e:load_level`, пример
`engine3d/games/dota/` (мини-дота с ботами).
Частицы, свет, погода, триггер-зоны, инвентарь/диалоги/магазин (`ui.lua`), катсцены, сохранения
(`save.lua`, через `Config`), билдер (F2), отладка (F3) - отдельные модули в `engine3d/`, API в
`ENGINE3D.md`. Игры без кода собирает `engine3d/kit.lua` из таблицы данных (пример `games/kit_demo`),
таблицу делает конструктор в `editor.html` + `editor_game.js`. Стандартные игры помечены
`builtin = true`: билдер их не меняет (у DOOM - только режим «Своя карта»), не снимай этот флаг.

## Стиль этой папки

- Первой строкой — `---@diagnostic disable: undefined-global`.
- Комментарии в коде на английском и объясняют **почему**, а не что.
- Всё, что видит игрок (меню, подсказки, надписи), — на русском.
- У каждого виджета меню — `:ToolTip(...)` с объяснением, у главных — иконка Font Awesome (`"\u{f0e7}"`).
- Настройки-числа выносятся в одну таблицу констант в начале файла.
